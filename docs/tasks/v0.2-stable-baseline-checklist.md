## 5. Static Safety Findings

### Episode runner

`scripts/run_episode.py` delegates execution to `kuavo_sim_platform.episode.run_episode`.
The runner creates a run_id and writes episode artifacts under:

```text
outputs/episodes/<run_id>/
```

The current artifact writer records:

```text
manifest.json
metrics.json
result.json
status.json
events.jsonl
stdout.log
stderr.log
latency_breakdown.json
external_timing.json
safe_stop.json for scenario entries
```

### Benchmark runner

`scripts/run_benchmark.py` runs benchmarks through the standard episode runner.
It refuses configs that appear to involve motion unless `--allow-motion` is
passed.

For D0, B/C must not pass:

```text
--allow-motion
```

### Web episode whitelist

The Web episode runner currently allows these experiment names:

```text
fast_health_check
read_only_interfaces
full_interfaces_check
```

`base_probe` is listed as disabled and is rejected by `POST /api/episodes/run`.
This is compatible with D0 because C can view and run read-only checks but cannot
start motion through the Web episode runner.

### Policy caveat for later A review

`configs/policies/v0.2_policy.yaml` currently gives B/C `allow_motion: true` and
allows `base_probe` as a task. The Web layer still rejects `base_probe`, and the
benchmark runner has an additional motion gate, but this policy setting is too
broad for `target_reach_random_1_3m_v0`.

Before any target reach motion config is added, A must either:

```text
1. narrow B/C motion policy for this task, or
2. add a task-specific permission level that only A can run.
```
